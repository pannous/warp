New tests run on the installed compiler: `WARP_NO_WINDOW=1 /Users/me/dev/bin/warp test test/types/test_instant_quantity.pairs.warp` fails both with `index out of range`. An experimental `instant_millis` in lib/time.warp checks dimensions with `same_quantity` and scales SI seconds to milliseconds; direct `instant_millis(2 seconds)` gives 2000, but neither `Instant(0).plus(2 seconds)` nor the addition succeeds. Even `use time; use units; Instant(0).plus(2)` returns `index out of range`, whereas `use time; Instant(0) + 2000` returns `Instant{ms: 2000}`. The experiment was removed, since it does not fix the outcome. Next isolate why importing units breaks explicit Instant method calls and whether the caller reaches the library method; separately investigate runtime local-time plus quantity. Numeric inputs should remain milliseconds and non-time dimensions should be refused. No existing tests changed.

Further isolation: `use time; Instant(0).plus(2)` returns `Instant{ms: 2}`, but `use time; use units; Instant(0)` alone returns `index out of range`; `use time; use units; 1` returns 1. A standalone `use units; class Moment { ms: int }; Moment(0)` returns `Moment{ms: 0}`, so the field name alone does not explain it. Next isolate which declaration in lib/time.warp interacts with units and find a general library fix, then reapply and test conversion. Smoke after the experimental library edit passed, but no feature outcome passed; no fix is claimed.

With a temporary minimal lib/time.warp, `class Instant { ms: int; plus(duration) := Instant(0) }` works under `use time; use units; Instant(0)`, but replacing the method body with `Instant(ms)` or `Instant(this.ms)` gives `index out of range`; `other() := ms` and `other() := this.ms` do too. The library declares the `ms()` unit. This points to a field/unit resolution interaction, though its core location is not yet established. The temporary module was restored exactly. Next investigate general field shadowing and resolution (including a differently named field/unit pair) before judging whether a library solution preserves the public `.ms` field.
