## warp 1.6.0 🚀

The fast release: the warp compiler compiling itself went from **820 s to 166 s CPU** in one day (2026-10-31), and
`warp rebuild` from 446 s to 225 s, with byte-identical output.

- **GC growth fixed.** wasmtime's copying collector grew its heap only once the active half was full, so it collected
  over and over freeing little: 80% of a big compile. It now doubles once half of that half is live
  (crates/wasmtime-capi/patches/copying-heap-growth.patch): 831 → 227 s, small programs' memory unchanged.
- **Four quadratic walks gone** in the compiler's passes: lambdas' later assignments, sugar listing the program five
  times per step, index positions and type tests / enums copying the whole scope into every function.
- **Faster parsing.** The parser tries only the words starting with the current character (30.4 → 16.0 s on core/),
  and every library file is parsed once per build.
- **Final GC types** for classes nobody extends: wasmtime tests them inline (is_subtype 8.5% → 1.4%).
- **Builds kept, never repeated.** Every compiler build is stored by its inputs hash with its whole record: inputs and
  sources, build log, CPU and memory, a function profile (WARP_PROFILE=perfmap). A failed build is kept with its log
  and failing step, and a lib-only change rebakes the stored compiler instead of compiling it again.
- **Phase timings**: `WARP_TIMES=1` marks each compiler phase; `scripts/profile.sh` profiles any warp run.
- **Units**: SI prefixes, long names and plurals, °C/°F, mph, ppi; `unit furlong := 201.168 m`; a unit after an
  expression (`x > 1500 m`); `3km as m`.
- **Typed parsing**: parse<T>(json) checks and builds nested objects and lists.
- Fixes: `int i=2*3`, `m.ms` beside a function `ms()`, use-os, files through absolute links, the ocean sample, and more.

Everything else as in [1.5.2](https://github.com/pannous/warp/releases/tag/v1.5.2).
