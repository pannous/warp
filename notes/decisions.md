# Decided questions: an inbox, not a law book

How decisions live (user 2026-11-10). A decision is one of three kinds, and each has its own permanent home:
1. Language rules (`type A < T` is a subtype, `÷` floors, markup only inside `html{…}`): the specification. Home: the
   wiki page of the topic, plus at least one outcome test line in test/. The wiki says what the language is, the test
   proves it and goes red when code drifts. Where the wiki and an entry here disagree, the wiki wins.
2. Process rules (quick merges, outcome tests only, where workers work): notes/agents/common.md or a role file.
3. Rulings for one moment (stage B waits for a seed, park this edge case, core OK for card X): the card and the
   commit message. They are not kept here.

This file is the inbox: a new decision lands here as one line with its key and date, and within a few days it is
absorbed into its home and deleted here (git keeps the history; the old-id index at the end names where it went). So
the file stays short and nothing in it lives long enough to go stale. Never read it front to back: grep a key or a
topic when the wiki and the tests are silent.
The regular round (card decisions-prune, every 3 days) absorbs entries into their homes and flags every entry the
current wiki, code or tests contradict; the flagged ones go to warp-interviewer as one batch question for the user:
keep, update or drop.
Decisions are taken in their moment and can be myopic or age. An agent who finds one blocking a clearly better design
says so with the reason (to warp-interviewer), instead of quietly obeying or quietly breaking it.
Open and parked questions: notes/open_decisions.md. Keys: P = interview questions, D = wiki-survey questions,
#n = the first question lists, slugs such as gpu-f32 for the rest; merged keys follow the survivor ("also: …").

## Process
- build-kinds-detected (user): page app, page wasm, site, wagi/server, wit and component outputs are warp build features, all Later, the server first; `warp build` detects the kind from the program itself (routes → a server, a page → its app, @primitive → native). Options are words (cli-words), not --flags.
- language-layers (user): notation (the parser, no keywords), kernel, and sugar as warp rewrite rules in extensions/sugar/ (migration plan notes/layers.md). Kernel: `:=` definitions, `=` assignment, call/member/`#`, function literals, if-then-else, `match` (not lowered to if chains), while with break/continue/return, class with variants, use, try-else, global, `data` quote, `rewrite` and `operator` declarations. Everything else (for, enum, unless/until, `?:`, `??`, `is T`, `as`, comprehensions, ranges, `n times`) is sugar. `n times {…}` is a plain library function `infix times(n: number, b: block)`; n-times-prelude-now: build block parameters and blocks that change outer variables now, then `times` is that prelude function; the sugar rule `rewrite $n times $body: block => for ·i in 1 to $n $body` is only a stopgap; `n times [x]` / `n times "ab"` stay list/text repetition.
- appends-line (supervisor): runtime errors and warnings end in their position "at line:col"; tests and guide expect it.
- alias-mechanism (user): one alias table lib/aliases.warp in warp data, one entry per canonical word: `add { operator: "+"  aliases: [plus, addiere] }`, `count { prefix-operator: "#"  aliases: [size, len, length] }`; an entry may name its operation (`add { symbol: Op.Add … }`); the aliases list is open-ended (other words and languages). Cards alias-mechanism, warp-signatures. alias-network (Later card): mutual lookup between a word and its aliases on classes (a class giving plus but not add makes `+` fall back to plus, and vice versa); richer data per alias (warns? shows as canonical?) maybe as @meta tags.
- alias-arrows (user): an alias names its direction with an arrow: `alias acos => arc_cosine` (new means existing) or `alias arc_cosine <= acos`; plain `alias acos = arc_cosine` is refused with the fix naming the arrow, and `warp fix` rewrites it (card alias-arc-cosine).
- operator-word-optional (user): one word suffices: `infix ⊕(a, b) := …`, `prefix √ := sqrt`, `suffix ‼(n) := …`; bare `operator ⊕(a, b)` takes its fixity from the parameter count (2 infix, 1 or `it` prefix); a class's `operator #(i)` stays its method (card operator-word-optional).
- after-sum (user): the prelude's `sum` carries its types in warp, `sum(xs: list): element of xs := fold(xs, 0, +)`. The linear-hint test for `sum(xs .* ys)` is ignored, naming the card for the warp-written analysis.
- name-glue: a rewrite template builds a visible name with `·`, `square·$a` → square_a_number, `$i·end`; it glues only inside templates and quoted code beside a $hole or symbol, numbers beside it multiply, plain `x·y` between values stays multiplication. Generated names name their rule in help and errors ("made by the rule at sugar/x.warp:12").

- warp-is-tests: the Rust tests' `is!("code", expected)` assertions also live as warp files, written `is! "3+3" 6`, where `is!` is a small warp function over eval: `def is!(warp: text, expected: any) := eval(warp) == expected` (failures report code, got, expected); names ending in `!` are definable words. Run with `warp test` through any pipeline switch. Card warp-is-tests. Test pairs as data: files hold code/expected pairs without repeated `is!`, loaded as data (map `test_pairs = { "1+1" 2 \n "√9" 3 }` or bare pairs). Matching is permissive: a result counts if warp's `==` says yes (1.0 ≈ 1 ≈ yes) or both sides are empty/falsy (0 ≈ ø ≈ [] ≈ no); warp's own `==` stays (0 == ø is no). The `is! "3+3" 6` line form stays for pairs exceeding the 80-character limit. Two kinds of files, not mixed: a pairs file of pure data (tab separated: code TAB expected TAB optional note, read as a list of lists), and ordinary warp test files with `is!` lines and other tests. A commented-out pair is a skipped test whose note names the regression's card (forward-crunch per line).
- wasm-instruction-body: a function or operator whose body is one wasm instruction says so: `prefix operator √(a: float): float := wasm f64.sqrt`, `floor(a: float): float := wasm f64.floor`, `min(a: float, b: float): float := wasm f64.min`. Arguments are evaluated onto the wasm stack in parameter order, the instruction consumes them and leaves the result; names and types only give the signature (and pick the overload). Replaces emitter.warp's hard-coded intrinsics table and FFI calls (libm) wherever wasm has the instruction. Multi dispatch: `√` is declared per type (`prefix operator √(a: exact): exact := a^(1/2)`), the argument's type picks the body: `√2.0` → 1.414…, `√16` → 4, `√2` → √2, `√-4` → 2ⅈ. Other small builtins may stay hard-coded until they need overloads.
- sound-buffer-lib (user): the host-filled sample buffer's words (new, count, get, set) are lib/sound.warp functions with `:= wasm` bodies over linear memory and a plain-warp bump allocator; no core file for it.
- pure-it-block: in the pure lane the `:=` form of an `it` block is enough (`f := { it + 1 }`); `f = { it + 1 }` defining a function of `it` is not required now (card pure-error, Later).
- unicode-glyphs: the warp lexer/parser never stops on an unexpected character: every Unicode character is consumed by its class (letters into names, symbols into operator/symbol tokens).
- call-takes-right: a function consumes everything to its right if it can: `square 3 + 1` → square(4) = 16, `2 * square 3` → 18, `print 1 + 2` prints 3. No spacing- or type-based tightening; parentheses split it: `square(3) + 1`. "If it can" is function-words-consume's fit to the parameter type (`count xs > 3` stops at the bool).
- leave-as-is batch: P237 `size`/`sort by size` (count of a list, no number meaning), P45 (a variable keeps its kind under `use script` too), exact 1/0 stays an error, no subscript log base (`log(100, 10)`).
- operators-are-functions: an infix, prefix or suffix operator is a normal function with a flag for its fixity, sharing arguments, signatures, types, overloads, `:= wasm` bodies and names in the wasm name section; no separate operator table. The only other difference is spacing: a function call needs spaces (`square 3`), an operator doesn't (`√2`, `a+b`, `3!`). fixity-operators-only (user): the flag is `enum Fixity { Prefix, Suffix, Infix }` on operators only; a plain function has no fixity.
- typed-builtin-variant (user): a typed definition named like a builtin (`sin(x: Real) := …`) adds a variant: values of its types take it, others keep the builtin (`sin 1.0` stays the float sin).
- method-by-type (user): `x.m(…)` is routed by x's type: a class receiver calls its method, a known other receiver keeps the word as written (`names.add(3)` on a list appends), only an unknown type is dispatched at run time.
- compiler-node-enum: the warp compiler uses the built-in node, no parallel class and no conversion: one warp declaration (core/node.warp) IS the built-in node's definition (emitter.warp derives the $Node struct from it), with the cases True, False, Empty, Number, Char, Text, Symbol, Error, Key, List, Data, Meta, Type (Op, Bracket, Separator as enums), so `Node` works as a type and in `match n { Key(left, op, right): … }` (cards node-enum, node-rewrite). Cases by name → Kind, fields by position → node parts. Op/Bracket/Separator cases print their name (`print Op.Add` → Add); `Op.Add as text` → "+", `"+" as Op` → Add; op_of/bracket_of/separator_of return the case.
- self-parser-drops: core/parsing/parser.warp leaves out foreign syntax (Rust macros, Python generators/yield from, Ruby blocks), music `go {…}`, phrase definitions (`to get price of item := …`), CSS in style; silently also WGSL shader holes and error nodes (`$a` pattern names stay: pattern-roadmap). Code is data: music and CSS need no parser syntax and work as library data DSLs (`tune d:data := play d` → `tune { c4 e4 g4 }`; `style {…}` reads its block as data).
- sugar-twins-drops: core/passes/passes.warp leaves out Rust Option forms (`if let Some`, `match o {Some/None}`, `unwrap_or`, `expect`, `is_some`; warp has `o != ø`, `o ?? d`, `o ?? raise(m)`) and the `set x to y` pass; setter-calls stands, `set x of y to z` comes back as a library code template.

- sugar-triage: web + markup, media + host, help + reflection passes stay out of the warp compiler and return as library code. `of`/`in` are right-associative infix operators (`length of characters in text` = `length of (characters in text)`), so the of extras are no special passes; forms that aren't a right-hand infix application are dropped or carded. `in`/`from` are a lookup only after a selector word (chars, words, lines, keys, …; one table), membership otherwise (in-bool); `print words in t` walks and `byte count of t` are dropped.
- #1 avoid panics, errors as values. #14 not-implemented errors unless easy.
- exports-kept: a module written for others (`warp compile --wasm` and the other module outputs) exports every top-level function under its name, so a JS host can call it; only a run (`warp run`, eval, tests) may drop an original nobody calls any more after specialising (card specialise-dead-originals). A function still mentioned (task by name, `&f`, an unspecialised call) always stays.
- package-reexport (card module-own): a package's own `use` lines reach the programs that use it: `use webgl` (which says `use draw`) alone gives draw's words too: `canvas(200, 100)`, `star(…)`, `save "x.png"`.
- Language name: warp everywhere; `.wasp` files still read; URLs/domains and wisp unchanged.
- uniscript-binary-import: `use uniscript` imports the released prebuilt uniscript_c.wasm (+ .h), committed in the uniscript repo at each release (uniscript-browser-wasm); warp's tests follow the released uniscript.

## Tooling: format, beautify, CLI
- prebuild-fails-loudly (user): a library that fails to prebuild fails the rebuild, naming the module and why; a module whose words are C imports (`… from "c"`, lib/wasmtime.warp) is source-only by itself, no marker comment. wasmtime-dropped: lib/wasmtime.warp leaves std_module_names; `use wasmtime` fails loudly as an unknown module; card wasmtime-self-hosted brings it back once foreign lines take structs.
- hello-size-exports (user): shown_at and trap_message are exported only from a program that can raise (raise/throw, a raising runtime word, a host word with arguments); hello ~1.5 KB; an engine trap in another program prints as wasmtime names it, without position.
- sample-spellings (user): samples are rewritten to the general forms (`int[height * width]`, `(y - center)^2`) instead of new syntax; no wish cards for those.
- drop-pure-word (user): `warp pure` is gone: plain `warp <file>` is the warp compiler (warp.wasm); `warp self` stays the self-built variant; `pure` survives only as a hidden CLI alias with a one-line note. Card drop-pure-word.
- warp-format: `warp format` (synonym `warp lint`, no `fmt`) only fixes layout in one canonical form, never meaning: tabs, `name: value`, spaced binary operators (glued only where spacing changes meaning; checked by comparing parse trees), list separators as written, `{` on its header's line, one space after `,`, none inside brackets, ≤ 1 blank line. Abbreviated words get a soft hint ("warp avoids abbreviations"), never a fix.
- beautify (also: beautify-preview): opinionated rewrites are `warp beautify`: prints the diff, asks "apply? y/n" in a terminal (piped lines answer it, one per file; end of input is no), `beautify yes` applies, `beautify check` previews; rules: hash-comments, alias words to their warp word via the I-meant fixes.
- cli-words: warp's command options are words, never `--flags` (`warp format check …`); card cli-words migrates the old ones.
- P102 `warp build hello.warp` makes the native executable; build-should: it writes x.wasm beside it, `--wasm` only the module. build-links: `warp build page.warp` opens the page in the system web view.
- no-executable-by-default: plain `warp file.warp` writes no executable (WARP_EXECUTABLE=1). P105 `warp run` never writes an executable nor takes the machine-code path.
- P77 an executable prints the output, then its value; exit 0, 1 on a trap; only an Int result is the exit status. P113 a ø result shows nothing. P236 `warp run` echoes the final value after the prints.
- P222 `warp serve [file] [port]` serves a page program; plain `warp app.warp` serves when the program declares a route/server; CGI mode retired.
- test-soft: `test C` records and continues, `check C` asserts, `test "name" {…}` is a test block. P209 test blocks run only under `warp test`. P210 all pass → one summary line; failures exit nonzero.
- fuel-metering: runaway loops are stopped by the epoch timer: 60 s CPU time by default (WARP_TIME_LIMIT), not for `warp build` executables or windowed/event-loop programs; the stop says how to raise it. Fuel (exact step budget, 4.4× on calls) only on request: `use fuel`, `warp fuel N app.warp`, WARP_FUEL, and compile-time folding of constant calls.
- fast-math: the polynomial math module is `use fast_math`; the CLI word is `warp fast app.warp`.
- P107 the playground offers only the .wasm download plus a `warp hello.warp` line. P108 Warp.sublime-syntax takes .wasp/.warp/.a/.angle. P229 double-clicking a .warp file opens the editor.

## Welcoming, diagnostics and newcomer forms
- kebab-hint-both-fixes: the kebab warning offers both fixes, "a_b or a - b".
- errors-name-file (user): every error, warning and hint, in every lane, prints file:line:column and the source line; a refusal never names internal words (`view·opaque`) but the user's code. Runtime errors and warnings keep their "at line:col" (card appends-line). Cards error-names, pure-error-candidate.
- Newcomer syntax is eaten, its intent compiled and the warp form hinted, only where it does not clash with a known footgun.
- Asks become got-it warnings; error-fallback cases (`[x]*n`, insert order, `[1 2 3]+4`, `1+2 squared`) stay loud errors naming the explicit forms (D3, D9/P5).
- Got-it scope: `[y = this one, a = all of this kind, n]`; an expression is remembered by its text; a `// got it` comment silences the line.
- warning-levels (also: hints-are-warnings): one Diagnostic with a level hint < weak < normal < severe; `--no-hints` and `use strict` are thresholds (notes/welcoming.md).

- canvas-zero: a missing setting takes a sensible default; errors only for an ambiguity too dangerous to guess.
- P75 fix buttons read "I meant: <replacement>", the meaning as a tooltip.
- julia-compat (user): stay close to Julia; its syntax is beautiful and its semantics often near perfect. Julia forms read with Julia's meaning; deliberate departures listed in wiki/Julia.md.
  - julia-floor-divide: `÷` is floor division as in Julia (synonym of `/!`, `7 ÷ 2` → 3), with a hint for newcomers expecting `/`.
  - julia-pair-range: `1:4` stays a pair; iterated (for, sum, comprehensions) a pair of two numbers is the range.
  - julia-text-times-hint: `"a" * "b"` concatenates with a got-it warning naming `+`; an error only when a text holds a number (`"3" * "4"`).
  - julia-dollar-interpolation: `"x is $x"` only as a toggled feature after the self-hosting migration (`$million`, `$0` clash).
- P78 modifiers from other languages (`public`, `static`, `inline`, …) are skipped with a got-it note; words with a warp meaning keep it.
- Word choices are not asked: the recommended word is canonical, synonyms are aliases with a note.
- foreign-spellings: foreign names are cheap aliases of existing words, not lowering code. Kept: Rust `<T>`/`let mut`, Enum.map/List.map/Seq.sum, Python lambda, variadic lambdas, JS destructured parameters, Ruby lambda/proc/blocks/to_s, C# LINQ, C++ `auto x`. Dropped: OCaml let-in and `fun`, Elixir `def …, do:`, C++ `[](…){…}`. R/PHP forms live in `use R` / `use PHP`. Kotlin `when x { 1 -> … }` = `match` with a warning; `match` takes `->` arms and `else`; `case` is optional before any arm.
- P157 no generic syntax: ported `fn id<T>(x: T)` compiles untyped with a note. P161 no Swift argument labels; ported labels compile with a note.
- P167 Go's `Point{1, 2}` builds `Point(1, 2)` for a known class with a note; unknown names stay tagged data.
- P145 R's `x <- 3` assigns with a note; `x<-3` is an error naming both readings; docs never use `<-`.
- P241 no vector type: `Vec<int>`, `vector<int>`, `Array<int>` read as `list of int` with the note "warp says list".
- Error highlighting: CLI carets under the word; web red/amber wavy underlines with the message on hover.
- #7/P92 unresolved calls are errors: `foo()` is "undefined function: foo"; a bare word statement naming nothing is "undefined variable: foo"; a bare `foo` in data stays a symbol.
- constant-words: null nul none nil nill nix nada nothing empty void true yes false no are constants in any case; `empty = 3` is `ø = 3`.
- function-words-consume (user): every function word, not only print, takes its arguments without parentheses, by its parameters (arity and types), no special rules: `show a, b` = show(a, b), `add 1 2` = add(1, 2), `print ord c` = print(ord(c)), `[twice 1, twice 2]` = [twice(1), twice(2)], `count xs > 3` = count(xs) > 3; a function word where the parameter takes a function is a value (`map square xs` = map(square, xs)); non-function words are unchanged. An argument reaches right as long as the expression fits the parameter type (`sqrt 4 + 5` = sqrt(9); `xs > 3` is a bool, so count stops). Varargs/defaults take what fits to the statement end, overloads the most arguments that type-check, a function value of unknown arity one atom per blank.
- spaced-definition-head (user): parentheses in a definition head are optional: `square x := x*x` defines square(x), `add a b := a + b` add(a, b); `f x` outside a definition stays a call.
- negated-call (user): minus binds weaker than application: `-f x` = -(f x), so `1 + -floor 2.5` → -1 and `-sin 0` → 0; `-a * b`, `-x^2` unchanged and `x=5; -x 1` stays [-5, 1] (a plain value is not a call).
- phrase-functions (user): a definition head may be a phrase with holes: `send v to c := c.send(v)`, `on every period (body: block) := timer_every(period, body)`, `await x within t or d := …`, `set field of object to value := …`; one phrase-row mechanism like the operator rows (~60–120 core lines), replacing ~35 lib rewrite rules (tasks, timers, signals, channels, english, which stay as such declarations).
- named-argument-phrases (user): a phrase is already an ordinary function called with named arguments: `give(v, to) := v + to; give 2 to: 40` → 42, `transfer 5 from: 1 to: 2`. Colonless phrase heads (`send v to c := …`) stay parked (phrase-params).
- phrase-rules-kept (user): `on change x {…}` / `on set x {…}` and `set name of p to 3` stay rewrite rules until name parameters (`f(x: name)`) exist, then become plain functions; `await all xs` / `await any xs` stay as written (notes/phrase_inventory.md).
- P86 adding values of unknown kinds builds `a + b` lazily; evaluated operands need Addable, else a type error.

## Comments, separators and lexing
- floor-division: `//` is always a comment; floor division is `/!` (`7 /! 2` = 3, `x /!= 2`); where `//` was clearly meant as division (`n = 7//2`), a strong warning names `/!` and `warp fix` rewrites it; `div` warns with the fix `/!` (`div` stays the html tag). A comment hiding a closing bracket is a parse error naming the `//`.
- hash-comments: `# text` is the preferred comment; `warp format hash-comments` rewrites `//` comments; the linter hints on `//`. `#` glued to a non-space is the count expression (`#s`); `#!`, `##`, `#use`/`#include`/`#import` stay comments/directives.
- `print a    print b` on one line is an error asking for `;`.
- P227 a comma next to `==` without parentheses is an error asking for them.
- P68 a braceless call whose argument holds an operator (`square 3 + square(4)`) warns naming both groupings. The prelude signature decides it: a word giving nothing (`: nothing`) has no second grouping and never warns. output-words-nothing: the output words (print, puts, puti, putl, putf) all give nothing.
- P143 `f x == y` is an error naming both groupings only when both type-check; P149 an untyped parameter's type is inferred from the body first. Statement words (print, return) take the whole expression.
- call-as-grouping: `f x as T` is `f(x as T)`, with a warning naming `f(x as T)` and `(f x) as T`.
- P189 extra control-flow words stay display-only keywords; ambiguous names need quoting.
- P165 soft keywords: hard keywords are control flow, declarations, literal values and module words (`fun` is hard, P165b); every other keyword is usable as a local name, parameter, field or method with a note. P172 alias words (`fire` for emit) yield to a program's own definition.
- unicode-symbols: warp parses Unicode symbol characters (arrows, math) as free operator names; an undefined use is "operator ⇔ is not defined". Arrow spellings of existing operators are alias lines in lib/math.warp with a "prefer ->" hint.
- operator-alias: math spellings of operators are alias lines in lib/math.warp keeping the precedence (`operator × := *`, `prefix operator √ := sqrt`).
- implicit-words-reserved: `it`, `self`, `this` are reserved: binding one warns (error under use strict); as the explicit parameter (`f(it) := …`) it is allowed.
- data-reserved: `data` is a keyword (the `data …` quoting prefix); a variable named data is an error.

## Numbers
- core-int-division (user): the compiler's source writes every integer division as `÷` (plain `/` of ints and every `/!` in core/ become `÷`; `/!` stays an alias), so the compiler needs no exact ratios and big numbers stay an optional extension.
- bool-int-fallthrough: a bool falls through to the int implementation of any operator.
- element-wise-scalars: element-wise operators apply to a non-list value directly (`3 .* 3` → 9).
- type-shows-nat (user): type(3) and an undeclared whole value show `nat`, a declared int shows `int`.
- fast-int-readings (user): a literal beside a fast int stays int (`xs[i + 1]` in a range loop); `i++`/`i--` on an undeclared counter stay int; `s += i` grows like + (a nat).
- int-boxed-overflow-big (user): + - * of two boxed ints that overflow give the big-int result instead of trapping (`xs = [2^62]; xs#1 * 4`).
- marked-floats-shape (user): `type X = float` beside `= int`; marks survive arithmetic (left mark, else right, only when the Kind matches, so `Color * 0.5` is plain); `°` an Angle shown in degrees, also when statically known and unboxed.
- exact-decimals: decimal literals are exact (`0.1 + 0.2 == 0.3`), division gives exact ratios; floats come only from float sources (transcendentals, sqrt of a non-square, host values, `as float`, float-typed places, e-notation) and are contagious; `==` warns only with a float involved.
- exact-power (user): a power of exact operands stays exact, a whole decimal exponent included (`0.5 ^ 1074.0` prints all ~750 digits of 2^-1074); the float pow is used only for float operands. Tests and probes keep their examples to calculations under ~10 s.
- int-list: a whole decimal literal is int (`type([0.0, 0.0])` is list of int, P196b); a variable's type joins every write. #21 `x=π; type(x)` is real.
- number-converts: `number` keeps an exact value; only `float` converts.
- float-text: floats print shortest round-trip digits (Python/JS repr) everywhere; P225 also joined to text.
- repeating-decimals: only the overline `0.3̅` is the exact 1/3; `x as decimal` writes the period overlined; never for floats.
- float-intervals (user): `±` says a value is not exact, so an interval (lib/intervals.warp) switches to fast floats. It shows only the digits its spread justifies: `(6.0m ± 0.3m) * (2.0m ± 0.2m)` is between 10.26m² and 13.86m², never 13.860000000000001; the float value itself is untouched; lib-only. interval-bounds-guard-digit (user): `low()`/`high()` hand out the bound rounded one digit finer than the ± text shows (12.0 ± 1.9 → bounds at 0.01: 10.26m² to 13.86m²); the interval keeps its floats. Ranges are written `A to B`. samples/units_dynamic.warp shows its pace by `pace.in("km/h")` rounded; exact arithmetic stays elsewhere (151/15 km/h).
- D16 `byte`, `int8..int32` are declared FFI types that trap on overflow; `u8` = `uint8` = `byte` (`int` and `nat`: nat-and-int). i64-wraps: `i64`/`int64` wrap silently at 2^63 like `fast int`; `use strict` catches it.
- c-int-names (user): C's multi-word integer names are the fixed widths C means, each with a got-it note naming warp's word: `unsigned int` = uint32, `unsigned long (long)` = uint64, `long long` = int64, `unsigned short` = uint16, `short int` = int16, `unsigned char` = byte, `signed char` = int8 (`x: unsigned int = -1` errors "uint32 overflow"). Single words keep warp's meaning (`long`, `int`: nat-and-int).
- fast-scope: `fast` before a function or module makes it machine arithmetic: polynomial sin/cos/exp/pow, `/` gives f64, ints are wrapping i64; `x: fast int` is i64.

- hex-printing: `255 as hex` is an int shown as 0xFF; arithmetic gives a plain int. binary-int: `5 as binary` shows 0b101.
- footgun-divzero: exact numbers raise divide by zero (catchable); computed IEEE floats give ∞/NaN.

## Types and annotations
- real-canonical-core (user): `real` is no longer a rational synonym (`exact` stays); `3 is real` yes; a program's own type of a core type word shadows it; a float given to `real` converts to the exact real (2.5).

- range-end-once: every `for` range end is evaluated once. #22 `N times {…}` evaluates N once; `i++ while c` is a plain while; `a = 2 if c` guards the whole assignment.

- #23 a loop's `it` shadows a function's `it`, with a warning. P174 `mk(k) := { it * k }`: `it` stays the parameter, with a warning. P239 in a lambda naming its parameter, `it` is the outer `it`.
- kebab-or-minus (user): `a-b` is a name when declared or bound; otherwise, with a and b bound, it is subtraction with a got-it note, and `warp format` prints `a - b` (`j = 5; i = 2; j-i` → 3); both existing → the name wins, with #6's warning.
- esoteric-phrases-commented (user): esoteric phrases in samples (`3 is at least 3`, `is at most`) are commented out with their canonical form beside them (`3 >= 3`), no rule words restored (card pure-reads).
- operator-even-spacing (user, like Swift): a binary operator is spaced evenly, both sides or neither; `1 +1` reads as `1 -1` does (the list `[1, +1]` with its warning), never as addition. `1 -1` and `1 +1` both give two items with "warning: … is two items; fix: 1 - 1"; an unevenly spaced operator with no prefix form (`a *b`) keeps computing, with the same warning where cheap.
- spaced-call-parentheses: `f (3)` is the call f(3) as `f 3` is; `f ()` calls f with no arguments as `f()` does (a one-parameter f gets ø), not a list `[f ø]`.
- dot-space-property (user): `p. b` as `p.b` is allowed only while it costs at most 2–3 core lines; otherwise it is refused with the fix `p.b`.
- default-parameter-def: `def f(n, i=2) = n + i` takes `i = 2` as a default parameter.
- #6 data as scope, warning when kebab parts are also variables; P81 that warning offers three fixes.
- stored-visits: `stored visits default 0`; `stored visits = 0` works with a note.
- Ranges: `r: 1..n` is the range itself; `upto` excludes the end with a hint. range-in-brackets: a range inside [ ] is one item, never spread.

## Functions and calls
- postfix-words (user): two rules. (1) backward application: a phrase of exactly two items, a value then a known one-parameter function, is the call, `4 square` → 16, `xs sorted` → [1, 2, 3]; one typed sugar rule (typed-rule-holes, `($x: any) ($f: any -> any) => $f($x)`), never inside `[…]` (`[1 f]` stays a list), a function first keeps prefix meaning (`square 4`). (2) an unbound word ending in -ed/-d looks up its stem as a one-parameter function with a got-it note (`xs reversed` → reverse(xs), `x doubled` → double(x)); two matching stems refuse naming both; at most ~20 core lines in name lookup, else parked.
- night-forms-kept (user): a def/fn header ending its line takes the body below (6 parser lines, def-body-next-line); `return a, b` returns the list [a, b]; `go for x in xs {…}` runs each iteration as a task, joined at the statement's end (needs its wiki line); a float repeat count known at compile time (`"ab" * 2.5`) is refused; `shared n = 0` is a main-level global for tasks.
- def-brace-body (user): a brace body without `:=` defines a function only after `def` or its alias words (`def f(x){x*2}`, fun, fn, function …), at no extra core cost; a bare `g(n) { … }` with g defined is a call with a block argument; with g defined nowhere it is refused, fix `g(n) := { … }` (refuse-never-guess: no definition by absence; cards gap-brace-def-no-assign, gap-fib-brace-body).
- map-all-test (user): the test reads as English, `all xs are even` and `are all xs even`, `any xs is even` and `is any xs even` (extensions/sugar/broadcasting.warp); the call all(xs, f) / xs.all(f) stays yes/no.
- map-all-canonical (user): `f all xs` is the canonical map (`moved all particles`), `xs.map(f)` its alias; the yes/no test over a list is map-all-test.
- int-overflow-shape (user): int-boxed-overflow-big keeps its ~23 lines with named overflow tests; no bit-trick or float shortcut.
- words-as-values (user): a function word used as a value is the lambda of its call (`f = sqrt; f(16)` 4, `apply(floor, 2.5)` 2), bringing its module; with several arities the one its use needs, never silently the first.
- definition-name-canonical (user): the name a definition carries is canonical for dir and everything warp prints (count stays count); internal names get canonical ones (map_keys → keys), old names become aliases or go.
- call-function-values: a glued `(` after a round group or an element calls a function value: `(x => x*2)(5)` 10, `adder(5)(1)` 6, `fs[0](3)`; numbers keep juxtaposed multiplication, `(2)(3)` 6, but no special code to keep it; if it breaks, a Later card.
- keywordless-def (superseded by def-brace-body: refused, no definition by absence): when f exists `f(x) { body }` stays a call with a trailing block (block-lazy-body).
- reflection: function objects have .name, .signature, .return_type, .parameters, .doc; printing one shows its doc above its typed .dump; `methods(x)` returns the function objects; `use reflection` adds compilation unit, compiler, origin, wasm index, effects. A bare parameterless function inside print/help/dump/type is called, with a warning and hint `function now`.
- function-in-list: in a list or text a function prints as its name; only alone it shows doc + definition.
- dir-lists: built-ins are function values of type `builtin` (a subtype of function); methods(x) lists them.
- default-methods: `x.word` ≡ `x.word()`, resolved by multi-dispatch on the receiver's type; a member or method of the object's own class is more specific and wins.
- class-members-free: built-in and library words are not keywords; class fields and methods dispatch on their class and never conflict; locals may shadow them.
- receiver-field-assign: `fresh(f: F) := { body = 99 }` writes f.body, same as in a class-body method (one-method-form, P115/P116); `let body = …` makes a local; any warning applies equally in both places.
- library-words-typed (also: dispatch-untyped-library-words): every library word has a full type signature and is immutable for its types; a program's untyped definition of the same name covers only other values, with a hint (`count(x) := 7; count([1,2])` → 2, `first(3)` → the program's).
- field-forms: plain fields take only `.` and `of` (read and set); call forms (`w(b)`, `b.w(5)`) are only for properties.
- cross-module-overload: definitions in different modules overload by argument type, no shadowing (`use script; sort ./names.txt` sorts lines, `sort [3 1 2]` the list); also for the program's own files: same-named definitions with different parameter types in two used files are legal multiple dispatch, chosen by the argument's actual type; until that dispatch is right, rename clashing helpers. static-dispatch: a declared argument type picks the variant written with it at compile time (`n: Node` takes the Node/any variant even for a text node); a value of no declared type is dispatched at run time by its actual type. list-variant-dispatch: `play(xs: list of note)` / `play(xs: list of file)` pick by the items at compile time where known, else at run time by every item's type, the same test as `xs is list of note` (a mixed list falls to a plain `list`/any variant or the no-variant error); an empty list fits every variant and takes the first declared one, a literal `play([])` with a got-it warning naming it and the explicit `[] as list of file`.
- random-forms: bare `random` is a float in [0,1) where a value is used; `random T` is a random value of type T (`random bool`, `random int`); `random(n)` 0…n-1; `random(a, b)` whole numbers inclusive, floats [a, b); `random 1..10` picks from the range. Any parameter of type Type accepts bare type words.
- function-references: a bare function name compared with a type or in `type(f)` is the function itself; `.floor` in argument position is a lambda (`xs.map(.floor)`, `people.sort(.age)`); `&floor` and `function floor` are the explicit references.
- declared-belonging (user): calling stays uniform (`f(x)` ≡ `x.f()` for every function, silently), but belonging is declared, not inferred from the first parameter: a function is a method of a type (dir, completion, docs, the playground's method list) only when declared in the class, the type's own module, or an extension; any other function is a free function of its module, dot-callable where that module is used (P171). A type alias carries its own methods (`type Name = text; argument_result(n: Name)` is a method of Name, not of text). class-extensions: outside code adds a method by its dotted name `text.shout() := upper(it) + "!"` (canonical) or groups several in `extend text { shout() := …; whisper() := … }`.
- path-literals-preferred (user): a path is written as a path literal without quotes (`./data/a.txt`, `~/x`, `/etc/x`, `../x`, `^/x`, `•/x`), never a quoted text, in samples, tests, docs and generated code; a quoted text given as a path (a file word's argument, a path-typed place) gets the "I meant" fix to the literal, which `warp fix` applies. - own-name-not-builtin (user): a program wanting its own version of a builtin math word (a Taylor-series sin) defines it under its own name (`sin_test`), not by redefining `sin`.
- library-own-words (user): a library file that needs an existing word (lib/extrema.warp's min, lib/fast_math.warp's sin) uses the existing one, never redefines it. `norm` (refused in lib/prelude.warp as the operator ‖) moves into the math module, visible only after `use math`. - builtins-name: library words are called builtins in notes, cards, messages and new code names; the Rust-only ones are "Rust builtins" until retired.

## Lists, maps and indexing
- ordinal-dot-index (user): no core rule and no plural guessing (`1.friend` is not a form). A program that wants `1.friends` as `friends#1` writes one overload of the dot, `infix operator .(i: int, a: any) := a#i`; that works on int literals. The general hook would be an overridable attribute access (`attribute(of, name)`), not built.
- each-field-broadcast: `xs.each.count` broadcasts a field or method over the items (`sum(counters.each.count)`); a list's own `.count` keeps its meaning; no field-wins-when-all-have-it (card xs-each).
- lazy-range-value (user): `a..b` / `a to b` hold only their two ends (a list node marked KindUnit.Range, `range` a type word, ~28 core lines); count, #, sum, indexing and iteration answer from the ends; any other list operation makes the items once, so a range stays a list everywhere (range-dots: `..` excludes its end).
- pair-items (user, ~4 core lines node_at/node_length): a key-value pair reads as two items, `p = (a: 1); p#1` → a (the name), `p#2` → 1 (the value), `#p` → 2; host item_count/item_at the same.
- bare-pair (user): `a:1` as a value is a pair; a word key stays the word as written, as `{a:1}`'s keys (`a = 5; x = a:1` is a:1, `x is pair` yes); any other key is its value (`1:4`); a computed key is `(a):1` → 5:1.
- to-inclusive (user): `a to b` always includes b, also when b is a length: walking 0-based indexes is `1 ..< #a` or `1 to #a - 1` (samples/lists/sorting.warp).
- #4/P40 `size` = count; bytes via `byte_size` / `number of bytes`; `len(x)` counts with a hint `#x`.
- P43 lists do not grow past the end: setting past it is a catchable `index out of range`.
- P34 a number subscript on an empty `{}` keys it as a map. map-subscript-runtime: the same at run time: `m[1]` on a value that is a map when the program runs keys it (`f(m) := m[1] + 1; f({1: 5, 2: 6})` → 6), on a list or text it stays a position (`f([5, 6])` → 7). single-entry: `{a:1}` stays a pair and becomes a one-entry map where a map is needed.
- stored-table-name: `stored people: [Person]` names its table after the variable; `… in "people_v2"` explicitly.
- markup-needs-html (user 11-09, replaces element-named-pair, card data-key-brings-markup): markup is written inside `html{…}`, or in a function known to return html (its result typed html), where a plain `b{"bold"}` still works; anywhere else a tag-named key or tag form is data: `x = {p: {c: 1}}; x` → {p: {c: 1}}, `{i: 1}` stays {i: 1}. - html-value (Interviewer, by markup-needs-html, card html-anywhere): markup is a value of `class Html { element: pair }` (a cheap class, not a subtype of pair: a pair would fill a subtype and data would count as markup), printed by its own `format` overload, rendered by dispatch on `is Html`. - format-types-inline-html (user 11-10, refines jsx under html-value, card inline-div-format): `warp format` turns inline HTML into warp markup and adds the html type where the element is a whole value: `p = <p>Hi</p>` → `p: html = p{ "Hi" }`, `f() := <div/>` → `f(): html := div{}`; elsewhere (an argument, inside an expression) the inline HTML stays as written.
- #25/#36 a space before `[` never indexes; only glued `a[..]`.
- P29 `pair.0` counts from 0. P30 `xs.pop()` gives the last item, `m.remove(k)` the value or ø.
- Word slices: `xs from #2 to #4`, `xs starting from #2`, `xs up to #2` or ordinals, both ends inclusive; a bare number is an error. P58 `xs#a..b` keeps the range with a strong warning naming `xs#(a..b)` and `(xs#a)..b`.

## Control flow, matching and errors
- comparison-after-arms (user): a comparison after a switch/match compares its value, never swallows the arms block: `switch 3 {1: "one" 3: "three"} == "three"` is yes, `match n {…} > 15` likewise; one general case in prefix_calls.warp fitted_comparison (~6 core lines), no per-operator rules.
- raw-rules (user, ~15 lines core/passes/rewrites.warp): a rule marked `where raw` fires top-down on its code as written, before the rules inside it; its result is rewritten bottom-up as usual (law, quote, test bodies).
- prefix-keyword-condition (user): a prefix keyword (whenever/when/on/at) takes its whole condition up to the trailing block (`alarm = whenever t > 30 {…}` is a listener handle); a glued digits:digits after a word stays one time value (`at 9:30 {…}`).

- for-over-iterator (user): a construction of a program class counts as an instance, so `for x in Countdown(3)` iterates by next() until ø.
- rewrite-rules (user): a rule set `rules { data($a * 1) => a; … }` is a value; calling it rewrites bottom-up to a normal form (a rewritten node is tried again until no rule fires: `simplify(data(y * 1 * 1 + 0))` → y); a step cap stops a rule set that never settles with a loud error naming the rule that keeps firing. `tree replace P with Q` stays a single pass.

- pattern-keyword: named patterns only with `pattern Adult = {age: >= 18}`; a plain `Name = …` is a value.
- #31 a switch without a match reports the run-time value (`no case for n = 4`).
- `if c {1} else 3+1`: the else takes the whole `3+1`.
- P21 `try X else Y`. P60 `try {…} catch {…}` and `try: … except:` are synonyms. P67 `catch e`: e is the Error value. #34 deep traps under `try` are caught. failed-raised: a raised error stops the program; bare `try X` turns it into the value (`r failed`). try-finally: `try X finally Z`.

A class is the type of a hole, like a typed hole that converts (`"0x" + h: hex`, `"v" + n: digits`, `c: digit`, `"/users/" + id: int`); class words digit(s), letter(s), hex, space, word are hole types only in a text pattern's hole position, nothing reserved (a variable `digits` stays plain).

## Signals, events and tasks
- finish-await (user): `finish job` is a soft alias of `await job` (a library word, not a reserved keyword; a program may define its own `finish`); `once job finishes` reads the same way.
- stopped-no-result (user): a cancelled task yields no result: after `cancel job`, reading or awaiting `job` raises an error ("job was cancelled"), so `try await job else -1` gives -1; never the value it would have computed. `stop job` / `job.stop()` is a synonym of `pause job` and warns "stop pauses job; to end it: cancel job". A stopped job resumes when awaited, so `job = go 3; stop job; job` → 3 (the final value is awaited).
- end-refused (user): `end job` is a compile error naming both readings, "end job: did you mean finish job (let it run to its end) or cancel job (end it now)?" — no default, since neither can be undone. Wiki: async.md "Controlling a task".

- after-condition (user): `after done return "third"` (also `after done "third"`) is a task that waits until the condition holds, then yields; await, cancel and `await t or fallback` as any task (stopped-no-result), as built in lib/tasks.warp (card unknown-name-after).
