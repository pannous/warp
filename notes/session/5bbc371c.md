Would it be common or allowed to rename tests to test and src to source?/////

---

## 🤖 Assistant

**Short answer: Technically possible, but highly non-idiomatic and not recommended.**

**`src/`** - Cargo's default. You *can* override it in `Cargo.toml`:
```toml
[lib]
path = "source/lib.rs"
```
But almost no Rust projects do this. Tools, IDEs, and developers all expect `src/`.

**`tests/`** - Cargo's convention for integration tests. There's no config option to rename it - you'd have to use `[[test]]` entries for each file manually.

**Why it's uncommon:**
- Breaks tooling expectations (rust-analyzer, cargo commands, CI templates)
- Confuses contributors familiar with Rust conventions
- No real benefit - everyone knows what `src` and `tests` mean

**What's actually seen in the wild:**
- `src/` is universal in Rust
- Some projects use `test/` (singular) for non-Cargo test frameworks or test data
- `source/` appears in C/C++ projects, almost never in Rust

If you're thinking about this for wasp/warp - I'd strongly recommend keeping `src/` and `tests/`. The Rust ecosystem is very convention-driven.
