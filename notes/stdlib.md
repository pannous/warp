# Standard library

Standard functionality split into importable modules, `lib/<name>.warp`. User docs: wiki/standard-library.md
(generated by `warp help --markdown`).

## 1. Principles
- Nothing that works breaks: prelude words stay global. New words go into modules; a module word used without its
  `use` is the error naming the module ("midi is in the standard module sound: write `use sound`",
  ffi::undefined_function_message), never a silent miss.
- Written in warp first: a module is a `.warp` file of ordinary definitions; a host word only where warp cannot do it
  (files, clock, network, processes), an adapter only where another ecosystem is far better. The same module then runs
  natively, in the browser and under AOT.
- One name, aliases with notes: `len`, `size`, `count` are one word; other languages' names (`str.upper`,
  `Math.sqrt`, `JSON.parse`, `re.sub`) work with a got-it note naming warp's word.
- P165 soft keywords: module names and words are soft: a program may name a local `text` or a parameter `count`; a
  program's own definition of a word wins, unless it is in `soft_keywords::SOFT_KEYWORDS`.
- Capabilities: modules that touch the outside declare it (src/analyzer/effects/mod.rs): file → Wasi/Host, net → Host,
  os/process → Process. `eval_untrusted` gets math, text, list, map, json, random-with-seed only.

## 2. Modules
Each module is `lib/<name>.warp`, embedded in the binary (modules.rs STD_MODULES, `include_str!`), so `use <name>`
needs no files and works in the browser. Non-standard modules (netbase) live in lib/extra/. lib/web.webidl is data
for web_idl.rs, not a module. `warp help` lists the modules, `warp help list` prints a module's leading comment and
its words with the comment line above each (src/modules/std_docs.rs).

Collections: other languages' class names (STD_CLASS_ALIASES, `new Set(xs)`, `collections.Counter(xs)`) and method
names (append appendleft popleft offer poll addFirst …, class_methods METHOD_ALIASES) work with a note on a class not
defining that name; `len(s)`, `count(s)` of an instance are its size method. A used module's classes go in before
class_methods (modules::insert_module_classes; the loader leaves them out, EARLY_CLASS_MODULES); a file module brings
all its classes, a std module only those the program names; a class the program declares itself wins.

## 3. Prelude and core
Three layers, each with one place in the source:
1. Core (compiler, Rust/wasm runtime): language forms, len/count, indexing, the runtime functions and host words.
   Where they are defined: library_words.rs SYNONYMS, RUNTIME_WORDS, EXPANDED_WORDS (list, sum, unwrap stay templates:
   the emitter dispatches on them); reflection/library_ops.rs LIBRARY_FUNCTIONS; text/text_builtins.rs
   TEXT_BUILTINS; lists/list_emitter.rs BUILTIN_CALLS; src/numbers/real.rs FUNCTIONS; src/host.rs HOST_WORDS.
   notes/library_words.md.
2. Prelude (`lib/prelude.warp`): first last round_to replace is_digit is_alpha is_alphanumeric hex_text binary_text …
   Loaded when the program or a used std module mentions a word in any spelling (modules::use_prelude,
   library_words::words_spelled_by: `isdigit`, `round(x, 2)` → round_to); its definitions are named `prelude·first`
   (modules::prelude_name), so a program's own `first` never meets them. A pass after modules::resolve must not add a
   prelude word. PRELUDE_WORDS (file's write, exists) bring only their definitions.
3. Modules, brought by `use`. The type modules list, text and map are the exception: their words are standard
   functions of every program, `unique(xs)`, `unique xs` or `xs.unique()` without `use` (decision
   type-library-words); `use list` only for the qualified `list.zip`.

## 4. Implicit modules
modules.rs IMPLICIT_MODULES, one table "module → when the program needs it": file URL → file (P183), a page → markup,
routes → router, a route's regular expression → regex; play, beep, stop_sound, wait_sound → sound (P171). No `use`
text is inserted (tests/modules/test_std_implicit_use.rs).

## 5. How a module is loaded
- `use math` resolves: a local `math.warp` (the file wins, except warp's own lib/<name>.warp, which is the embedded
  module itself: modules.rs is_embedded_std_file) → the embedded `lib/math.warp` → an FFI library (`m`) → the package
  registry. `use cmath` is libm alone (P169/P191).
- `use a, b` and `use a b` load each; `from list import zip, unique` brings only those words; `import list` works.
  Not yet: `import list as l`, `from collections import Counter` of classes.
- Names: after `use math`, `gcd(a, b)` and `math.gcd(a, b)` both work (P170); a program's own `gcd` wins. A program
  variable `text`/`list` keeps its methods.
- The loader keeps a std module's definitions aside and gives the program only those it calls, and those they call
  (`with_needed_definitions`): an unused word would compile with parameters of no kind. A module word inside an
  interpolation counts (modules::template_holes).
- A module's source gets the program's early passes (pipeline::lower_module_source) and its getters are lowered with
  the program. Its initial parse is muted; `normalize::show_hint` rejects positions under embedded lib/<module>.warp.
- Modules calling modules: a std module may `use` another (lib/text.warp `use list`). A module only std modules use
  is hidden from the program: Loader::hidden_apart renames its words `lib·drop` in the std definitions (a word a
  used module defines itself stays). A file module's `use` counts as the program's
  (tests/modules/test_std_module_uses_module.rs).

### Coverage (card std-word)
tests/modules/test_std_coverage.rs fails naming every lib/*.warp word no test calls: a word is covered when a test
(tests/**/*.rs or .warp) names it, or a covered word's body calls it. src/ doesn't count: its alias tables
(modules.rs `("acos", "arc_cosine")`) name words without calling them. A new lib word needs an is! test; the words
nothing else tested are in tests/modules/test_std_words.rs (native and browser).

## 6. Known gaps
- A constant fractional exponent (`x ^ (1/3)`) is a float power; one held in a variable still traps.
- sqrt/cbrt have no alias: they are the operators √ ∛.
- `none(xs, f)` is the null (card none-call); a name `end` after else is Ruby's block end (card end-variable).

## 7. Adapters
How a module word is backed when warp alone cannot do it (notes/stdlib_connectors.md, notes/wasm_modules.md).

| adapter | native | browser | `warp build --exe` | eval_untrusted | values |
|---|---|---|---|---|---|
| A host word (Rust in warp, src/host.rs; JS twin in web/playground/host.js) | yes | yes, if host.js has the twin | only the stub's words (print, libm, sleep, random, random_below, clock) | per capability | Nodes both ways |
| B C library compiled to wasm (`use zlib` → zlib.wasm, types from its header) | yes | yes, same module | not yet | sandboxed, a candidate | numbers, texts, byte buffers, out-pointers |
| C native C FFI (dlopen + headers) | yes | no | refused | refused (Ffi) | numbers, texts, handles |
| D WIT component (`use wasm "lib.wasm"`) | yes | yes (jco) | refused | sandboxed, a later question | WIT types ↔ Nodes, resources as handles |
| E Python (`use python`) | python3 child | Pyodide | stub starts python3 | refused (Ffi) | JSON, handles |
| F JavaScript (`use js`) | node child | the page's globalThis | stub starts node | refused (Ffi) | JSON, handles |

Rule (P183): a std module works in every host without anything installed, so it uses warp, A (a Rust crate already
in warp's dependencies natively, the browser's built-in API in host.js) or B (a C library compiled to wasm once).
C, E and F need a library, python3 or node on the machine: they stay the user's `use python numpy`, never a std
module's backing. Where the two hosts' engines differ (Rust regex vs JS RegExp), the module defines the common subset;
a feature only one engine has is a loud error in both ("… is not in warp's regex (one engine lacks it)": look-around,
backreferences), never a different result.

Per module: json serde_json / JSON.parse (to_json of a non-JSON value is a loud error); hash sha2 + crc32fast / a
synchronous JS twin (crypto.subtle is async, a host call cannot wait); regex Rust regex / RegExp (flag u); net ureq /
synchronous XMLHttpRequest (the browser obeys CORS); file WASI natively, in the browser in memory and on a page in
IndexedDB (store `files` of database `warp`, read back before the first run; read sees them first, then the served
repository); os env is ø and args [] in the browser, exec the error naming the native host. B stays the way for
xxhash, compression and other libraries without a Rust/JS pair; zlib.wasm is a candidate std module.

### How an adapter word is built (A)
Two host words carry every adapter: `std_pure(module, member, arguments)` for words without effects (json, hash,
regex: capability like libm's) and `std_io(…)` for words that touch the outside (file, os, net: Host, IO). A std module
defines its words over them, `parse_json(text) := std_pure("json", "parse", [text])` (lib/json.warp); natively
src/modules/std_adapters.rs answers by (module, member), in the browser host.js STD_ADAPTERS. Values cross as for the
foreign runtimes (foreign.rs json_of / node_of, host.js plainOfTree / treeOfPlain). Their results are any Node
(analyzer ANY_VALUE_WORDS); the wrappers' parameters are annotated `any` (`to_json(value:any)`): an unannotated
parameter fed only by such values would default to an int.
Adding a word: one match arm in std_adapters.rs, one function in STD_ADAPTERS, one line in lib/<module>.warp, a test
run natively and in the browser.

Other ecosystems' names (src/lowering/welcoming/std_aliases.rs, before welcome_forms): `JSON.parse` / `json.loads`,
`JSON.stringify` / `json.dumps`, `re.findall(p, t)` → find_all(t, p), `re.sub(p, r, t)` → replace_all(t, p, r),
`fs.readFileSync` → read, `fs.writeFileSync` / `appendFileSync` / `existsSync`, `os.getenv` → env, `process.exit` →
exit: the note names warp's word, and the alias brings its module. A program that names the module (`re = 3`) or
imports the real one (`use python "json"`) keeps it (tests/modules/test_std_aliases.rs).
