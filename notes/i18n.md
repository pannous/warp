# i18n: translations as data (card web-i18n)

`use i18n` (std/i18n.wasp, written in wasp, tests/web/test_i18n.rs). Translations are plain data, one map per language:

```wasp
use i18n
messages = {
	en: { hello: "Hello {name}", cart: { one: "{count} item", other: "{count} items" } }
	ru: { cart: { one: "{count} товар", few: "{count} товара", many: "{count} товаров" } }
}
translate(messages, "ru", "cart", { count: 3 })   // "3 товара"
plural_category("pl", 22)                          // "few"
```

- A message is a text with `{name}` holes filled from `values`, or a map of CLDR plural categories
  (zero one two few many other) picked by `values["count"]`; a category the map lacks falls back to `other`.
- Lookup order: the language (`de-AT`), its base (`de`), then the first language of `messages` (the source language).
  A key no language has is an error, `no translation of <key>` (loud, never an empty text).
- plural_category covers whole numbers for: other-only (ja zh ko th vi id ms), fr/hi (0 and 1 are one), ru/uk/be,
  pl, cs/sk, ar, and one/other for the rest (en de es it nl sv …). Fractions (CLDR's v/f operands) are not modelled.
- Message holes are `{name}` inside quotes: wasp does not interpolate `{…}` in a text, so the holes stay data.

Open (not done here): the page's language (html lang, the browser's navigator.language) as the default; focus
management on route change waits for web-router (card web-i18n keeps that part).
