# is! tests as warp files (card warp-is-tests, decision warp-is-tests)

The Rust tests' `is!("code", expected)` assertions also live as warp files beside their Rust file, two kinds, never
mixed: a pairs file of pure data with the short tests (tests/numbers/test_math.rs → tests/numbers/test_math.pairs.warp),
one test a line, tab separated: code ⇥ expected ⇥ an optional note (user decision, supervisor 2026-10-19):

```
'2+3*4'	14
'0-1'	-1	a note
// 'fib 10'	55	card fib-memo: regression
```

and an ordinary warp file (tests/numbers/test_math.warp) with an `is!` line for each test whose pair would be longer
than 80 characters, whose code spans lines, or whose expectation is computed (`1 + pi`):

```warp
is! 'use sin;sin π' 0
```

- Warp's own reader takes a pairs file as a list of lists: a tab between two items of a line separates columns
  (Separator::Tab, looser than `;`, tighter than a newline; scanning.rs `at_tab_separator`); indentation and a tab
  before a comment or the line's end separate nothing. An empty column keeps its place (`'y'⇥ø⇥note`).
- Under `warp test` a file whose every statement is a pair (or the code alone, expecting ø), or `test_pairs = {…}`
  holding them, becomes is! checks (test_blocks.rs `pairs_checked`).
- A commented-out pair is a skipped test, its note naming the card of the regression that broke it: `warp test` prints
  `⊘ skipped "fib 10" 55: card fib-memo: regression` (test_blocks.rs `skipped_pairs`). So a commit breaking a few lines
  can land: forward crunch per line.
- Matching is permissive (lib/prelude.warp is!): `got == expected`, or both empty/falsy (0 ≈ ø ≈ [] ≈ no).

- `is!` is lib/prelude.warp's `is!(warp: text, expected: any)`: `eval(warp) == expected`; a failure prints
  `✗ is! "3+3" 7: got 6`. Programs may define it the user's way, `def is!(warp: text, expected: any) := …`; the prelude
  keeps its `name(…) := …` form (its readers take no `def`).
- Bang words: a name glued to `!` is one word when the program or a standard module defines it
  (warp_parser declaration_scan `defined_name`, atoms.rs `bang_word`, lookahead.rs `defines_bang_word` keeps `is!` from
  reading as the operator `is`). Undefined, the `!` keeps its meanings: suffix (`x!`, `name! email?`), macro
  (`println!(…)`), `!=`.
- `warp test`: a top-level `is!` call counts as a test (test_blocks.rs CHECK_WORDS); its error (code that fails) fails
  only its line. A plain run runs it as the call it is. `warp test a.warp b.warp …` sums the files.
- Code goes in single quotes (`'…'`, `«…»` when it holds a quote): nothing interpolates there. A negative or computed
  expectation goes in parentheses: `is! '0-1' (-1)`.

## Generating
`scripts/is_tests.py` writes every file (header "generated by …"; edit the Rust test, then run the script again) and
counts what it skipped: code that is no literal/const/format! of consts (helper functions, loops), Rust-only
expectations (Node::Symbol, error values, texts of lists, divisions: `1.0 / 3.0` is a ratio in warp), #[ignore] tests.
2026-10-19: 10498 of 12063 written into 1602 files (pairs and is! files) (skipped: 715 code no literal, 508 #[ignore], the rest Rust-only
expectations). Comments are `#` lines (warp format's hint).

## The fast lane
`scripts/is_tests.py run [normal|emitter|pure] [-- files]`: `warp test` per file, 4 at once, WARP_EMIT_REFUSALS per
lane; counts and logs in data/is_tests/. Lanes: normal (Rust), emitter (WARP_SELF_HOSTED=1), pure
(WARP_SELF_HOSTED=pure). A file without its summary (crash, timeout, a lane that missed the is! lines) counts its
lines as unrun. One lane takes ~25 min (4 processes).
- 2026-10-19 normal: 9114 passed, ~1329 failed, 32 unrun (two files over 300 s, one crash: card py-run) of 10475.
  Most frequent failures: π / time literals can't cross into eval's block (card eval-code), prelude words "called but
  not loaded" inside eval (card code-run), "no implicit conversion" (Rust's is! compares a text expectation loosely).
- emitter and pure: everything unrun: parser.warp parses the test file too and reads `is!` as `is` + `!`, so no test
  counts (card parser-reads-2, warp-parsing).

## Known gaps (cards)
- eval of code holding π (Number::Real), time literals, nan, inf, complex: "parse_code: π cannot cross to another task
  yet" (the code crosses into the program as data, host/tasks/values.rs TaskValue): card eval-code.
- Each is! compiles its code in a module of its own through the host (run_block): ~0.1–0.2 s a line.
- The pure lane's parser.warp has no bang words yet: `is! '…' 6` reads as `is` + `!` there.
