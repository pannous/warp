# Offline builds for cloud agents: the `vendor` branch

Purpose: cloud sandboxes (Claude Code cloud sessions / routines) cannot reach crates.io, so they cannot `cargo build`.
The `vendor` branch carries the vendored crates (`vendor/`, generated by `cargo vendor`) so they can build and test
offline in seconds instead of waiting ~10 minutes per GitHub CI round trip.
The same text is in CLOUD_OFFLINE_BUILD.md at the root of the `vendor` branch.

main does not track `vendor/` (it is in .gitignore, ~276 MB), and main's `.cargo/config.toml` has NO source replacement:
local builds use the registry cache in ~/.cargo (`offline = true`).

## Use it (cloud agent, any branch)
    git fetch origin vendor && git archive origin/vendor vendor | tar -x
    cargo test --offline --no-fail-fast \
      --config 'source.crates-io.replace-with="vendored-sources"' \
      --config 'source.vendored-sources.directory="vendor"'
`vendor/` stays untracked (ignored), never commit it to a work branch.

## Refresh it (after Cargo.lock changes: a missing crate shows as "no matching package named …")
Needs network (a local machine): in a clean export of main, `cargo vendor --config net.offline=false vendor`, verify the
offline build above with an empty CARGO_HOME, then commit main's tree + `vendor/` as a merge commit on top of the old
`vendor` tip (fast-forward push, no force). Add vendored files with `git -c core.autocrlf=false add -f vendor`:
the global autocrlf=input rewrites CRLF files and breaks cargo's `.cargo-checksum.json`.
